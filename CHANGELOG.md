# Changelog

## 0.6.0 — the Markdown engine

A third engine, and the first that renders at run time rather than compiling
to modules. The template engines are unchanged.

### Added

- **A Markdown engine**, `beamai_markdown`: CommonMark 0.31.2 (652/652 spec
  examples) with markdig's thirty extensions, each passing its own markdig
  spec file, and four renderers -- HTML, plain text, normalize (canonical
  Markdown) and roundtrip (649/649 byte-exact). A port of markdig by way of
  cl-markding. Pipelines are plain maps; there is no cache, no ets, no
  process. See [docs/markdown.md](docs/markdown.md).
- **`beamai_markdown_transform`**: a literal `beamai_markdown:inline/1` call
  folds to its HTML at compile time, and `-markdown_document({Name, Path})`
  renders a file into `Name/0` and `Name_iolist/0`, both through the
  module's `markdown_opts`.
- The markdig data tables (Unicode categories, HTML5 entities, emoji, bidi
  ranges) as generated modules, with `tools/gen_markdown_data.py` to
  regenerate them.

## 0.5.0 — the Jinja2 engine

beamai_render now ships two template engines side by side. Mustache is unchanged in
behaviour; everything below is either new or a consequence of making room for
the second engine.

### Added

- **A Jinja2 engine.** Full expression language, `if`/`for`/`set`/`with`/
  `filter`/`raw`/`do`, template inheritance (`extends`, `block`, `super()`),
  macros (`macro`, `call`, `import`, `from`), `include`, whitespace control,
  autoescaping with safe propagation, 53 builtin filters and 33 tests.
  Compiled to Erlang modules exactly as mustache templates are: no cache, no
  ets, no process. See [docs/jinja.md](docs/jinja.md).
- **`rebar3 jinja`**, and a `jinja_opts` configuration block. Both engines may
  share one `views` directory and one `out_dir`; each generated file names its
  engine in its banner, and each provider only collects its own orphans.
- **`beamai_jinja_transform`**, the same three source forms as the mustache
  transform: `-jinja_ext`, `beamai_jinja:inline/2`, `-jinja_template`. Both
  transforms can be applied to one module.
- **`beamai_jinja_dev`** and **`beamai_html_dev:reload_all/0`** for development-time
  reloading.
- **520 conformance fixtures** in `test/jinja_spec/`, generated from CPython
  `jinja2` 3.1 by `tools/gen_jinja_fixtures.py` and committed, so the test
  suite still needs nothing but OTP.
- A shared layer -- `beamai_html_forms`, `beamai_html_text`, `beamai_html_escape`,
  `beamai_html_path`, `beamai_html_engine` -- holding everything that is genuinely
  independent of which template language is being compiled.

### Changed

- **Generated modules record their compile options as a sorted list rather
  than a map.** A map is printed in `maps:to_list/1` order, which follows the
  VM's atom table, so the same build run twice could produce different bytes.
  Build stamps are unaffected, so this forces no rebuild. Anything reading
  `opts` out of a `-mustache_source` attribute needs `maps:from_list/1`;
  `beamai_mustache_dev` already accepts both shapes.
- **Build stamps are computed with `term_to_binary(..., [deterministic])`**,
  which sorts map keys. Only projects using a non-empty `ext_opts` will see a
  stamp change, and then only once.
- The banner of a generated file now names its engine:
  `%% Generated by rebar3_beamai_render (mustache) from ...`. Files written by 0.4.x
  are still recognised as mustache output.
- `#mopts.compiler_opts` is now `#mopts.engine_opts` (internal to the plugin).

### Deprecated

- `beamai_mustache_text` and `beamai_mustache_path` are forwarding shells for
  `beamai_html_text` and `beamai_html_path`. They will be removed in 0.6.

## 0.4.0

A full rewrite: templates compile to Erlang modules, standard mustache context
stack semantics, zero dependencies. See the README for the migration notes.
